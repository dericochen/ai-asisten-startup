# Database

PostgreSQL is authoritative for all company state. By default an embedded PostgreSQL (PGlite, WASM) persists to `data/pglite`, so no server is needed. Set `DATABASE_URL=postgres://…` to use a real PostgreSQL server. Both use the same Drizzle schema and SQL migrations (`server/drizzle`), applied automatically at startup.

## Tables

| Area | Tables |
|---|---|
| Company | `company` (name, mission, Owner policies JSON), `owners`, `owner_sessions` |
| Organization | `departments`, `roles` (level, authority, Kiro agent, capabilities), `employees` (status, current task/activity) |
| Work | `projects` (phase, status, progress, counters, deployment config, URLs), `tasks` (stage, steps, progress, round, attempts, runtime, cost, branch, input/result) |
| Runtime | `agent_runs` (KIRO/FALLBACK, provider, model, profile, worker, session, status, error class, fallback reason, output, credits, cost), `tool_calls` (policy decision + reason) |
| Fallback | `provider_connections`, `secrets` (AES-GCM ciphertext, IV, tag, masked value) |
| Governance | `approvals` (gate, approver role, required authority, evidence, decision, decider authority), `artifacts` (versioned), `decisions`, `meetings`, `messages`, `ceo_messages`, `memories`, `notifications` |
| Delivery | `check_runs` (suite, name, status, details), `releases` (version, commit, gate results), `deployments`, `monitor_samples`, `incidents` |
| Trail | `events` (timeline + SSE), `audit_log`, `counters` (human-readable codes) |

To change the schema, edit `server/src/db/schema.ts`, then run `npm run db:generate` and commit the generated SQL.

Back up the database by stopping the server and copying `data/` (database, Kiro home, repos, master key). Without `data/secrets/master.key` (or `ACO_MASTER_KEY`), stored fallback keys cannot be decrypted.

# Project system

A project is created by the CEO (from an Owner command) or directly by the Owner. It gets a code (`PRJ-003`), a CEO sponsor, a Product Manager, a local git repository at `data/workspaces/<PRJ>/repo` with `main` and `develop` branches and a generated `.gitignore`, and deployment ports.

- **Tasks**: generated by the workflow engine per phase, each with role, assignee, dependencies, steps (progress), round, attempts, runtime, cost and result. Statuses: BACKLOG, READY, WORKING, REVIEW, QA, BLOCKED, DONE, FAILED, CANCELLED.
- **Git**: engineers work in `agent/<TASK>` worktrees; the platform commits as `<Employee Name> (AI) <code@agents.company.local>` and merges into `develop` (never `main`). Releases merge `develop → main` and tag.
- **Project page tabs**: Overview (progress, next gate, health, working now, blockers), Timeline, Research, Product, Design, Architecture, Engineering (branches, commits, build/review checks), Tasks (Kanban/table), QA, Security, Deployments (release gates, logs), Monitoring, Meetings & Decisions, Artifacts, Costs.
- **Completion**: COMPLETED only after production validation passes, N healthy monitoring probes, and the CEO completion report.
